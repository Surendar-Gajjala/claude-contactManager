# cmsPrompt — ContactManagerApp Full-Stack Development Specification

## 1. PROJECT OVERVIEW

### Application Name
ContactManagerApp

### Objective
Build a simple full-stack Contact Management application for managing Persons and Contacts.

The application must support:
- Person CRUD operations
- Contact CRUD operations
- Person-name search
- Pagination
- Sorting
- Form validation
- Excel file upload for bulk Person and Contact creation
- Proper Person-to-Contact relationship management

### Architecture Rules
- Use a simple layered architecture.
- Do not use microservices.
- Do not implement authentication or authorization unless explicitly requested.
- Do not over-engineer the application.
- Keep controllers thin.
- Keep business logic inside services.
- Use repositories for persistence.
- Use DTOs for API requests and responses.
- Never expose JPA entities directly from controllers.
- Use global exception handling.
- Follow clean naming conventions and REST API best practices.

The Excel file must contain:
- FirstName
- LastName
- Email
- Gender
- Address
- PhoneNumbers
- ContactType

Example:
FirstName: Surendar
LastName: Reddy
Email: surenda@gmail.com

PhoneNumbers: 9618443676, 7893097820
ContactType: HOME, PERSONAL

The import must create one Person record and the appropriate Contact records.

# 24. EXCEL PHONE NUMBER AND CONTACT TYPE MAPPING RULE

If an Excel row contains:
PhoneNumbers: 9618443676, 7893097820
ContactType: HOME, PERSONAL

Process the comma-separated values individually.

Rules:
1. Split PhoneNumbers using a comma.
2. Split ContactType using a comma.
3. Trim leading and trailing whitespace.
4. Create one Contact record for each phone number.
5. Map phone numbers to contact types by position.
6. First phone number → first contact type.
7. Second phone number → second contact type.
8. Continue positional mapping for all values.

Mapping:
PhoneNumber[0] → ContactType[0]
PhoneNumber[1] → ContactType[1]
PhoneNumber[2] → ContactType[2]

# 25. EXCEL IMPORT EXAMPLE

Input:
PhoneNumbers: 9618443676, 7893097820
ContactType: HOME, PERSONAL

Expected:
| Person | Phone Number | Contact Type |
|---|---|---|
| Surendar Reddy | 9618443676 | HOME |
| Surendar Reddy | 7893097820 | PERSONAL |

Both contacts must reference the same Person.

# 26. EXCEL VALIDATION RULE

The number of phone numbers must exactly match the number of contact types.

Valid:
PhoneNumbers: 9618443676, 7893097820
ContactType: HOME, PERSONAL

Invalid:
PhoneNumbers: 9618443676, 7893097820
ContactType: HOME

If the counts do not match, reject the Excel row with a clear validation error.

Do not create incomplete or incorrectly mapped Contact records.

# 27. EXCEL IMPORT TRANSACTION RULE

The Excel import operation must be transactional.

Flow:
Upload Excel
→ Read Excel
→ Validate Excel structure
→ Validate all rows
→ Create Person records
→ Create Contact records
→ Commit transaction

If processing fails, roll back the transaction.

Do not leave incomplete Person or Contact data in the database.

# 29. PERSONS DATABASE TABLE

Table: persons

| Column | Type | Constraints |
|---|---|---|
| id | BIGSERIAL / UUID | PRIMARY KEY |
| first_name | VARCHAR(100) | NOT NULL |
| last_name | VARCHAR(100) | NOT NULL |
| email | VARCHAR(255) | NOT NULL, UNIQUE |
| gender | VARCHAR(20) | NOT NULL, CHECK IN (MALE, FEMALE, OTHER) |
| address | VARCHAR(255) | NULL |
| created_at | TIMESTAMP | NOT NULL DEFAULT now() |
| updated_at | TIMESTAMP | NOT NULL DEFAULT now() |

# 30. CONTACTS DATABASE TABLE

Table: contacts

| Column | Type | Constraints |
|---|---|---|
| id | BIGSERIAL / UUID | PRIMARY KEY |
| person_id | BIGINT / UUID | NOT NULL, FOREIGN KEY → persons.id |
| phone_number | VARCHAR(20) | NOT NULL |
| contact_type | VARCHAR(20) | NOT NULL, CHECK IN (PERSONAL, HOME, WORK, OTHER) |
| created_at | TIMESTAMP | NOT NULL DEFAULT now() |
| updated_at | TIMESTAMP | NOT NULL DEFAULT now() |

Database ContactType values must match the backend enum values.

# 31. DATABASE RELATIONSHIP AND DELETE RULE

Relationship:
persons.id → contacts.person_id

One Person can have multiple Contacts.

When a Person is deleted, all associated Contacts must be deleted automatically.

Use:
FOREIGN KEY (person_id)
REFERENCES persons(id)
ON DELETE CASCADE

Configure the JPA relationship consistently with the database behavior.

# 32. DATABASE INDEXES
